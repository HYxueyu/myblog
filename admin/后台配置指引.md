# 后台配置指引（Decap CMS）

> 目标：打开 `https://blog.heiyunas.top/admin`，用 GitHub 登录，直接在网页上改游戏墙 / 阅读墙 / 影视墙。
>
> **本地已全部打通**（后台界面能正常渲染、显示"使用 GitHub 登录"）。
> **只剩最后一步**：给 GitHub 登录配一个"中转站"（OAuth 代理），因为 GitHub 不允许网站直接登录。

---

## 一、为什么需要这一步

网页上的"使用 GitHub 登录"按钮，不能直接跳去 GitHub。GitHub 规定：**必须有一个服务器持有 `client_secret`，替网站完成握手。**

这个"服务器"就是 OAuth 代理。它做三件事：

```
你的浏览器  ──①点登录──▶  blog.heiyunas.top/api/auth
                              │
                              ▼
                        【OAuth 代理】
                              │
                    ②带着 client_secret 找 GitHub
                              │
                              ▼
                         GitHub 验证
                              │
                    ③发一张临时通行证回来
                              │
                              ▼
                        后台登录成功 ✅
```

因为我们网站是纯静态（没有服务器），所以这个代理得单独部署一个。

---

## 二、方案选择

| 方案 | 难度 | 费用 | 推荐度 |
|---|---|---|---|
| **甲：Cloudflare Worker**（自己部署） | 中 | 免费 | ⭐⭐⭐⭐⭐ |
| **乙：DecapBridge**（第三方托管） | 低 | 免费 | ⭐⭐⭐ |

**建议选甲。** 理由：代码在自己手里，不依赖第三方存活；而且你本来就有 Cloudflare 账号和 `heiyunas.top` 域名。

## 三、方案甲：Cloudflare Worker 完整步骤

### 前提检查

- [x] 你有 Cloudflare 账号（`blog.heiyunas.top` 在上面）
- [x] 域名 `heiyunas.top` 的 DNS 托管在 Cloudflare
- [ ] 需要在 GitHub 上建一个 OAuth App（下面第 2 步）

---

### 第 1 步：创建 GitHub OAuth App

1. 打开 https://github.com/settings/developers
2. 点左侧 **OAuth Apps** → 右上 **New OAuth App**
3. 按下面填写：

| 字段 | 填什么 |
|---|---|
| **Application name** | `小筑后台` （随便填） |
| **Homepage URL** | `https://blog.heiyunas.top` |
| **Authorization callback URL** | `https://blog.heiyunas.top/api/auth` |

4. 点 **Register application**
5. 页面出现 **Client ID** → **复制保存**
6. 点 **Generate a new client secret** → **立刻复制保存**（这串只显示一次，关掉就再也看不到）

> ⚠️ 这两串是钥匙，**不要发给任何人、不要写进 GitHub 仓库**。后面要填到 Cloudflare 里。

---

### 第 2 步：部署 OAuth Worker

Worker 代码我已经写好了，在 `my-blog/oauth-worker/`（单文件、无依赖、约 150 行）。

**方式一：一键脚本（推荐，不用装任何东西）**

先创建一个 Cloudflare API Token：

1. 打开 https://dash.cloudflare.com/profile/api-tokens
   （如果打不开，用这个备用入口：登录后点右上角头像 → **My Profile** → **API Tokens**）
2. 点 **Create Token** → 找到 **Create Custom Token** → **Get started**
3. 按下面配权限：

| 类型 | 权限 | 级别 |
|---|---|---|
| Account | Workers Scripts | Edit |
| Account | Workers KV Storage | Edit |
| User | User Details | Read |

4. Account Resources 选你的账号，点 **Continue to summary** → **Create Token**
5. **复制生成的 token**（只显示一次）

然后在 `my-blog` 目录开终端，依次执行：

```bash
cd my-blog

set CF_API_TOKEN=刚复制的token
set GH_CLIENT_ID=第1步的ClientID
set GH_CLIENT_SECRET=第1步的ClientSecret

node tools/deploy-oauth.js
```

脚本会自动上传 Worker、绑定环境变量、输出访问地址。**成功的话你会看到 `🎉 部署完成`。**

> 如果报 `无法获取账号列表`，说明 token 权限没配全，回第 3 步补上再试。

**方式二：wrangler 命令行**

```bash
cd my-blog
npx wrangler deploy --config oauth-worker/wrangler.toml
npx wrangler secret put GITHUB_CLIENT_ID --config oauth-worker/wrangler.toml
npx wrangler secret put GITHUB_CLIENT_SECRET --config oauth-worker/wrangler.toml
```

**方式三：网页部署第三方现成版**

1. 打开 https://github.com/sveltia/sveltia-cms-auth
2. 点 **Deploy to Cloudflare Workers** 按钮
3. 按提示授权、命名（比如 `xiaozhu-oauth`）

---

### 第 3 步：确认环境变量

如果用**方式一**（脚本），环境变量已自动配好，**跳过这步**。

如果用 wrangler 或网页部署，需要手动配。打开 Cloudflare 控制台 → **Workers & Pages** → 找到 Worker → **Settings** → **Variables and Secrets** → 添加：

| 变量名 | 值 | 类型 |
|---|---|---|
| `GITHUB_CLIENT_ID` | 第 1 步复制的 Client ID | Secret |
| `GITHUB_CLIENT_SECRET` | 第 1 步复制的 Client Secret | Secret |
| `ALLOWED_DOMAINS` | `blog.heiyunas.top,localhost:8899` | Text |

保存后 **重新部署一次**（Deploy 按钮）。

---

### 第 4 步：把 Worker 挂到 /api/auth

让 `blog.heiyunas.top/api/auth` 指向 Worker。**三种做法，选一种。**

**做法 A：Cloudflare Worker 路由（推荐）**

Cloudflare 控制台 → 你的 Worker → **Settings** → **Triggers** → **Add route**：

```
blog.heiyunas.top/api/auth
```

Zone 选 `heiyunas.top`。保存。

**做法 B：`_redirects` 代理（最简单，需 Worker 有公开地址）**

如果部署脚本输出了 `https://xiaozhu-oauth.<xxx>.workers.dev`，在 `my-blog/_redirects` **最顶部**加一行：

```
/api/auth*  https://xiaozhu-oauth.<你的子域>.workers.dev/api/auth:splat  200
```

保存后推送，CF Pages 会自动生效。

**做法 C：Pages Functions（随网站一起部署）**

告诉我，我把 Worker 代码改写成 `functions/api/auth.js`，跟网站同仓库部署，**连 Worker 都不用单独建**。

---

### 第 5 步：验证

1. 打开 `https://blog.heiyunas.top/admin`
2. 点 **使用 GitHub 登录**
3. 会跳去 GitHub 授权页 → 点 **Authorize**
4. 跳回后台 → **应该看到"游戏墙 / 阅读墙 / 影视墙"三个菜单**

## 四、方案乙：DecapBridge（如果不想折腾 Worker）

1. 打开 https://decapbridge.com 注册（用 GitHub 登录）
2. 建一个 site，填 `HYxueyu/myblog`
3. 它会给你一个 `base_url`，改 `admin/config.yml`：

```yaml
backend:
  name: github
  repo: HYxueyu/myblog
  branch: main
  base_url: https://<它给你的地址>
  auth_endpoint: auth
```

4. 提交推送，完成。

**代价**：登录经过第三方服务器。介意就别用。

## 五、配置完成后能做什么

登录后你会看到三个菜单，点进去就能：

| 操作 | 怎么用 |
|---|---|
| 改标题 / 类型 / 平台 / 状态 | 直接点字段改，下拉框选 |
| 改评分 | 填数字，支持 4.5 这种 |
| 改短评 / 长篇观后感 | 多行文本框，支持 Markdown |
| **换封面** | 点"封面图"→ 上传，自动存到 `posters/` |
| **加一条新游戏/书/电影** | 点"Add 游戏"，填完保存 |
| **删一条** | 条目右上角的删除按钮 |
| **调整顺序** | 拖动条目左侧的手柄 |

**保存 = 自动提交到 GitHub = Cloudflare 自动重新构建**（约 1-2 分钟生效）。

## 六、常见问题

**Q：点登录报 `redirect_uri mismatch`？**
A：GitHub OAuth App 里的 **Authorization callback URL** 必须**一字不差**是 `https://blog.heiyunas.top/api/auth`。少个斜杠、多个空格都不行。

**Q：点登录跳去 GitHub 后报 404？**
A：第 4 步的路由没配好。确认 `blog.heiyunas.top/api/auth` 能访问到 Worker。

**Q：登录成功但看不到内容 / 报 403？**
A：Worker 的 `ALLOWED_DOMAINS` 要含 `blog.heiyunas.top`，且 GitHub 账号得对仓库 `HYxueyu/myblog` 有写权限。

**Q：后台一直白屏？**
A：本地已验证界面正常。线上白屏的话按 F12 看 Console 报什么错，发我。

**Q：上传的封面图去哪了？**
A：自动进 `posters/` 文件夹，和现在手工放的位置一样。

## 八、安全说明

- `client_secret` **只存在 Cloudflare Worker 的环境变量里**，不进仓库、不进浏览器 ✓
- 后台地址带 `noindex`，搜索引擎不收录 ✓
- 登录后 GitHub 只授予你账号对**这一个仓库**的写权限 ✓
- 其他人打开 `/admin` 只能看到登录页，登录不了（除非你给他们仓库权限）✓
