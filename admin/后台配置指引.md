## 一、整体是怎么运作的

```
你的浏览器  ──①点"使用 GitHub 登录"──▶  blog.heiyunas.top/api/auth
                                              │
                                              ▼
                                    【Pages Function】
                                    functions/api/auth.js
                                              │
                                    ②带着 Client Secret 找 GitHub
                                              │
                                              ▼
                                         GitHub 验证
                                              │
                                    ③发一张临时通行证回来
                                              │
                                              ▼
                                        后台登录成功 ✅
```

**为什么需要这个中转**：GitHub 规定 `client_secret` 不能出现在浏览器里，必须有个服务端替网站完成握手。

这个"服务端"就是 `functions/api/auth.js` —— 它已经写好了、也部署上线了，**你不需要建任何东西**。

## 二、你需要做的两件事

### 第 1 件：创建 GitHub OAuth App，拿到两串钥匙

1. 打开 https://github.com/settings/developers
2. 点左侧 **OAuth Apps** → 右上 **New OAuth App**
3. 按下表填（**注意 Homepage 和 Redirect 不一样**）：

| 字段 | 填什么 |
|---|---|
| **Application name** | `小筑后台`（随便填） |
| **Homepage URL** | `https://blog.heiyunas.top` |
| **Application description** | 留空 |
| **Authorization callback URL** | `https://blog.heiyunas.top/api/auth` |

> ⚠️ **最容易填错的地方**：
> - **Homepage URL** 只要域名，**不带** `/api/auth`
> - **Authorization callback URL** 才要带 `/api/auth`
>
> ❌ `Allow wildcard matching` —— 不要勾
> ❌ `Enable Device Flow` —— 不要勾
> ⬜ `Expire user access tokens` —— 勾不勾都行

4. 点 **Register application**
5. 复制 **Client ID**
6. 点 **Generate a new client secret** → **立刻复制**（只显示一次）

> 如果 `github.com` 打不开（DNS 问题），试试切手机热点。

---

### 第 2 件：把这两串钥匙交给 Cloudflare

**现状说明**：OAuth 代理代码（`functions/api/auth.js`）已上线，线上已验证它接管了 `/api/auth`。
现在缺的只是「把 Client ID / Secret 写进 Cloudflare 项目环境变量」这一步。

#### 路线 A（推荐）：在 Cloudflare 控制台直接填 —— 最直观

1. 打开 https://dash.cloudflare.com
   - 登录后进 **Workers & Pages**（左侧栏）
   - 点进项目 **`xiaozhu`**
   - 上方标签 **Settings** → 左侧 **Variables and Secrets**（环境变量）
   - 点 **Add**，加两条：

   | 名称（区分大小写） | 值 | 类型 |
   |---|---|---|
   | `GITHUB_CLIENT_ID` | 第 1 步的 Client ID | Text |
   | `GITHUB_CLIENT_SECRET` | 第 1 步的 Client Secret | **Secret**（加密） |

   - **Environment 选 Production**（Preview 也可一起加）
   - 保存

2. 回到项目 **Deployments** → 最近一次部署右侧 **⋯** → **Retry deployment**
   （**必须重部署，环境变量才生效**）

> 如果你能在浏览器里打开控制台，**走这条最省事，不用管下面所有内容**。

---

#### 路线 B：用脚本调 API（控制台打不开时的备用方案）

我这个环境里 `dash.cloudflare.com` 的 DNS 时好时坏，所以准备了脚本兜底。

##### B.1 创建 Cloudflare API Token

1. 打开 https://dash.cloudflare.com/profile/api-tokens
2. **Create Token** → **Create Custom Token** → **Get started**
3. 配权限：

| 类型 | 权限 | 级别 |
|---|---|---|
| Account | Cloudflare Pages | Edit |
| User | User Details | Read |

4. **Account Resources** → Include → **明确选中你的账号**（这一步最关键，见下方警告）
5. **Continue to summary** → **Create Token** → **复制**（只显示一次）

> ⚠️ **已实测的坑**：如果 Account Resources 没真正选中账号，token 虽然"有效"，
> 但 `GET /accounts` 会**返回空数组**（CF 不会给任何权限提示），导致脚本无法自动定位账号。
> 表现：`/user` 返回 200，但 `/accounts` 和 `/zones` 都是空列表。
> **遇到了就重新建一个 token，或走 B.4 手动传 account_id。**

##### B.2 找到 account_id（备选，脚本自动不行时用）

三种拿法，任选：

- **控制台右侧栏**：`dash.cloudflare.com` 登录后，右侧 Account ID 直接复制（32 位）
- **从网址看**：URL 形如 `dash.cloudflare.com/<32位ID>/...`，那段就是
- **问我要**：把上面任一方式拿到的 ID 贴给我，我接着跑

##### B.3 跑脚本

在 `my-blog` 目录**用 PowerShell**（不是 CMD）：

```powershell
cd my-blog

$env:CF_API_TOKEN="B.1步的token"
$env:GH_CLIENT_ID="第1步的ClientID"
$env:GH_CLIENT_SECRET="第1步的ClientSecret"
# 如果 B.2 拿到了 account_id，再补一行（脚本自动定位失败时必须）
$env:CF_ACCOUNT_ID="32位account_id"

node tools/set-pages-env.js
```

脚本会：
- 自动定位账号（`/accounts` → 失败则 `/zones` 反查 → 再失败则提示你传 `CF_ACCOUNT_ID`）
- 自动找到 Pages 项目（认 `heiyunas` 域名，项目名是 `xiaozhu`）
- 把两串钥匙写进 production + preview 环境变量
- 全程日志同时写到 `tools/set-pages-env.log`

看到 `🎉 完成` 就好了。**只看这一行不够——记得做 B.4 重部署。**

##### B.4 重新部署

环境变量改动**必须重新部署才生效**：

- 控制台：项目 → Deployments → 最近一次 → **Retry deployment**
- 或者随便推一次代码（`git commit --allow-empty -m "redeploy" && git push`）

## 六、常见问题

**Q：点登录报 `redirect_uri mismatch`？**
A：GitHub OAuth App 里的 **Authorization callback URL** 必须**一字不差**是 `https://blog.heiyunas.top/api/auth`。少个斜杠、多个空格都不行。
（**Homepage URL** 则只填 `https://blog.heiyunas.top`，不带路径。）

**Q：`/api/auth` 返回 500，提示 `GITHUB_CLIENT_ID 未配置`？**
A：环境变量还没写进去，或写了但**没重新部署**。走第 2 件，然后务必 Retry deployment。

**Q：脚本说「/accounts 返回空，无法自动定位账号」？**
A：这是 CF 的经典坑——API Token 的「账户资源」没真正选中账号时，`/accounts` 静默返回空数组（不给权限提示）。
解法：① 重新建 token 并确认选中账号；② 或从控制台复制 Account ID，用 `$env:CF_ACCOUNT_ID="..."` 传给脚本。

**Q：登录成功但看不到内容 / 报 403？**
A：GitHub 账号需要对仓库 `HYxueyu/myblog` 有写权限。

**Q：后台一直白屏？**
A：按 F12 看 Console。本地和线上我都实测过界面正常，白屏八成是 `admin/vendor/decap-cms.js` 没上传成功。

**Q：后台能改文章和相册吗？**
A：暂时不能，现在只管三面墙。要加跟我说。

## 七、技术细节（给以后排查用）

| 文件 | 作用 |
|---|---|
| `functions/api/auth.js` | OAuth 代理本体（Pages Function） |
| `_routes.json` | 限定 Functions 只处理 `/api/*`，避免静态资源走 Functions 消耗配额 |
| `tools/set-pages-env.js` | 用 CF API 配环境变量（绕开打不开的控制台） |
| `tools/test-function.js` | 本地模拟 Pages 环境跑单测（13 项） |

**几个已踩过的坑**：

1. **`_redirects` 的 SPA 兜底不会截胡 Functions** —— CF Pages 的路由优先级是 Functions 高于 `_redirects`。线上实测确认。
2. **但 `_routes.json` 必须写** —— 不写的话默认 `include: ["/*"]`，所有请求（含图片）都进 Functions，白白消耗免费配额。
3. **回调地址要硬编码** —— Function 里写死 `https://blog.heiyunas.top/api/auth`，不能靠 `url.origin` 推导（预览域名会导致不匹配）。
4. **token 交换要有超时** —— 已加 15 秒 `AbortController`，避免 GitHub 无响应时请求挂死。
5. **CF API Token 的「账户资源」必须真选中账号** —— 否则 token 显示"有效"（`/user` 200），但 `/accounts`、`/zones` 全部返回**空数组**，且不给任何权限错误提示。这是 CF 的已知行为（官方社区有多起同题）。
6. **拿 account_id 的兜底顺序** —— `/accounts` 列表 → `/zones` 反查（`zone.account.id`）→ 环境变量 `CF_ACCOUNT_ID` 手动传。前两条都可能因权限配置而空，所以第三条必须留着。
7. **本机网络**：`HTTP_PROXY` 指向死代理（端口开但上游不通），Node https 会自动读 → 全部 TIMEOUT。脚本里显式 `delete process.env.*_PROXY`。
   另外系统 DNS 不稳定，脚本用自建 `dns.Resolver`（223.5.5.5 等）解析 + IP 直连 + **显式 `Host` 头**（不带 Host 会被 CF 边缘判 403）。

## 九、安全说明

- `client_secret` **只存在 Cloudflare 的项目环境变量里**，不进仓库、不进浏览器 ✓
- `ALLOWED_HOSTS` 白名单校验 Origin，防止开放重定向 ✓
- 后台地址带 `noindex`，搜索引擎不收录 ✓
- 登录后 GitHub 只授予你账号对**这一个仓库**的写权限 ✓
- 其他人打开 `/admin` 只能看到登录页，登录不了（除非你给他们仓库权限）✓
