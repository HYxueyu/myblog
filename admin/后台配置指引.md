# 后台配置指引（Decap CMS）

> 目标：打开 `https://blog.heiyunas.top/admin`，用 GitHub 登录，直接在网页上改游戏墙 / 阅读墙 / 影视墙。
>
> **进度**
> - ✅ 后台页面已上线 —— `https://blog.heiyunas.top/admin` 能打开，显示"使用 GitHub 登录"
> - ✅ 数据层已迁移 —— 内容存在 `data/*.json`，页面直接读
> - ⬜ **只剩最后一步**：给 GitHub 登录配一个"中转站"（OAuth 代理）
>
> **这最后一步需要你操作**（约 10 分钟，只做一次），因为要用到你的 GitHub 和 Cloudflare 账号。
> 照着做就行，不用懂技术。

---

## 一、为什么需要这一步

网页上的"使用 GitHub 登录"按钮，不能直接跳去 GitHub。GitHub 规定：**必须有一个服务器持有 `client_secret`，替网站完成握手。**

这个"服务器"就是 OAuth 代理。它做三件事：

```
你的浏览器  ──①点登录──▶  blog.heiyunas.top/api/auth
                              │
                              ▼
                        【OAuth 代理】
                              │
                    ②带着 client_secret 找 GitHub
                              │
                              ▼
                         GitHub 验证
                              │
                    ③发一张临时通行证回来
                              │
                              ▼
                        后台登录成功 ✅
```

因为网站是纯静态（没有服务器），所以这个代理得单独部署一个。

---

## 二、先看这条：你这台机器的特殊情况

我实测过了，**`dash.cloudflare.com`（Cloudflare 控制台）在你当前网络下 DNS 解析不出来，打不开**。

但 **`api.cloudflare.com` 是通的**。

所以：
- ❌ **不要**走"打开控制台手动点"和"wrangler 登录"这两条路 —— 会卡住
- ✅ **要**走下面的一键脚本 —— 它直接调 API，绕开打不开的控制台

脚本我已经写好放在 `tools/deploy-oauth.js`。

> 另外 `github.com` 也可能打不开（DNS 问题）。第 1 步如果进不去，试试切手机热点，或者告诉我。

## 三、三种方案对比

| 方案 | 难度 | 费用 | 说明 |

## 四、方案甲：Cloudflare Worker（一键脚本）

### 第 1 步：创建 GitHub OAuth App

1. 打开 https://github.com/settings/developers
2. 点左侧 **OAuth Apps** → 右上 **New OAuth App**
3. 按下面填：

| 字段 | 填什么 |
|---|---|
| **Application name** | `小筑后台`（随便填） |
| **Homepage URL** | `https://blog.heiyunas.top` |
| **Authorization callback URL** | `https://blog.heiyunas.top/api/auth` |

4. 点 **Register application**
5. 页面出现 **Client ID** → **复制保存**
6. 点 **Generate a new client secret** → **立刻复制保存**（这串只显示一次，关掉就再也看不到）

> ⚠️ 这两串是钥匙，**不要发给任何人、不要写进 GitHub 仓库**。

---

### 第 2 步：创建 Cloudflare API Token

1. 打开 https://dash.cloudflare.com/profile/api-tokens
2. 点 **Create Token** → 找到 **Create Custom Token** → **Get started**
3. 按下面配权限：

| 类型 | 权限 | 级别 |
|---|---|---|
| Account | Workers Scripts | Edit |
| Account | Workers KV Storage | Edit |
| User | User Details | Read |

4. Account Resources 选你的账号 → **Continue to summary** → **Create Token**
5. **复制生成的 token**（只显示一次）

---

### 第 3 步：一键部署

在 `my-blog` 目录开终端，依次执行（把三个值换成你自己的）：

```bash
cd my-blog

set CF_API_TOKEN=第2步的token
set GH_CLIENT_ID=第1步的ClientID
set GH_CLIENT_SECRET=第1步的ClientSecret

node tools/deploy-oauth.js
```

脚本会自动上传 Worker、绑定环境变量、输出访问地址。**成功会看到 `🎉 部署完成`。**

常见报错：
- `无法获取账号列表` → token 权限没配全，回第 2 步补
- 网络错误 → 说明 `api.cloudflare.com` 也不通了，告诉我

---

### 第 4 步：把 Worker 挂到 /api/auth

脚本会输出一个地址，形如 `https://xiaozhu-oauth.xxxx.workers.dev`。

**最省事的做法**：打开 `my-blog/_redirects`，**在最顶部**加一行（地址换成脚本输出的）：

```
/api/auth*  https://xiaozhu-oauth.xxxx.workers.dev/api/auth:splat  200
```

保存 → 推送（`node tools/push-mirror.js`）→ 自动生效。

> 也可以告诉我，我帮你改成 Pages Functions 版本，连 Worker 都不用。

---

### 第 5 步：验证

1. 打开 `https://blog.heiyunas.top/admin`
2. 点 **使用 GitHub 登录**
3. 跳去 GitHub → 点 **Authorize**
4. 跳回后台 → **应该看到"游戏墙 / 阅读墙 / 影视墙"三个菜单**

## 五、方案乙：Pages Functions（最省事的技术方案）

把 OAuth 逻辑直接放进网站仓库，CF Pages 自动部署。**不需要建 Worker、不需要配路由、不需要管 workers.dev 地址。**

跟我说一句「用 Pages Functions」，我会：
1. 创建 `functions/api/auth.js`
2. 把 `oauth-worker/index.js` 的逻辑搬过去
3. 你只需要提供 GitHub Client ID / Secret

> 环境变量同样要在 CF 控制台配，控制台打不开的话我可以用 API 帮你配。

## 六、方案丙：DecapBridge（最省事，走第三方）

1. 打开 https://decapbridge.com 注册（用 GitHub 登录）
2. 建一个 site，填 `HYxueyu/myblog`
3. 它给你一个 `base_url`，改 `admin/config.yml`：

```yaml
backend:
  name: github
  repo: HYxueyu/myblog
  branch: main
  base_url: https://<它给你的地址>
  auth_endpoint: auth
```

4. 提交推送，完成。

**代价**：登录经过第三方服务器。介意就别用。

## 七、配置完成后能做什么

登录后你会看到三个菜单，点进去就能：

| 操作 | 怎么用 |
|---|---|
| 改标题 / 类型 / 平台 / 状态 | 点字段直接改，下拉框选 |
| 改评分 | 填数字，支持 4.5 这种 |
| 改短评 / 长篇观后感 | 多行文本框，支持 Markdown |
| **换封面** | 点"封面图"→ 上传，自动存到 `posters/` |
| **加一条新游戏/书/电影** | 点"Add 游戏"，填完保存 |
| **删一条** | 条目右上角的删除按钮 |
| **调整顺序** | 拖动条目左侧的手柄 |

**保存 = 自动提交到 GitHub = Cloudflare 自动重新构建**（约 1-2 分钟生效）。

## 八、常见问题

**Q：点登录报 `redirect_uri mismatch`？**
A：GitHub OAuth App 里的 **Authorization callback URL** 必须**一字不差**是 `https://blog.heiyunas.top/api/auth`。少个斜杠、多个空格都不行。

**Q：点登录跳去 GitHub 后报 404？**
A：第 4 步的路由没配好。确认 `blog.heiyunas.top/api/auth` 能访问到代理。

**Q：登录成功但看不到内容 / 报 403？**
A：代理的 `ALLOWED_DOMAINS` 要含 `blog.heiyunas.top`，且 GitHub 账号得对仓库 `HYxueyu/myblog` 有写权限。

**Q：后台一直白屏？**
A：按 F12 看 Console。本地和线上我都实测过界面正常，白屏八成是 `admin/vendor/decap-cms.js` 没上传成功。

**Q：上传的封面图去哪了？**
A：自动进 `posters/` 文件夹，和手工放的位置一样。

**Q：后台能改文章和相册吗？**
A：暂时不能，现在只管三面墙。要加跟我说。

## 十、安全说明

- `client_secret` **只存在 Cloudflare 的环境变量里**，不进仓库、不进浏览器 ✓
- 后台地址带 `noindex`，搜索引擎不收录 ✓
- 登录后 GitHub 只授予你账号对**这一个仓库**的写权限 ✓
- 其他人打开 `/admin` 只能看到登录页，登录不了（除非你给他们仓库权限）✓
